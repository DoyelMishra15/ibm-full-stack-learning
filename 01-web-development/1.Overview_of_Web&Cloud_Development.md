# Overview of Web and Cloud Development

## 1. How Does a Website Work?

When you open a website, your web browser communicates with a server to request and receive the information needed to display the website.

### Basic Flow

```text
User
  ↓
Web Browser (Client)
  ↓
Request
  ↓
Server
  ↓
Response
  ↓
Web Browser
  ↓
Website Displayed
```

### Example

When you enter a URL such as `www.ibm.com` into your browser:

1. The browser contacts the server associated with the website.
2. The browser requests the information needed to display the website.
3. The server processes the request.
4. The server sends a response containing the required data.
5. The browser uses that data to display the website.

---

## 2. Client and Server

### Client

A **client** is the system or application that requests information from a server and uses the server's response.

For websites, the **web browser** acts as the client.

Examples of web browsers:

* Google Chrome
* Microsoft Edge
* Mozilla Firefox
* Apple Safari

### Server

A **server** is the system that receives requests from clients and sends back the information required by the client.

### Client-Server Model

```text
Client → Request → Server
Client ← Response ← Server
```

The client requests information, and the server responds with the required data.

# 3. Technologies Used to Build Websites

For most websites, three important technologies are:

| Technology     | Purpose                                |
| -------------- | -------------------------------------- |
| **HTML**       | Defines the structure of a webpage     |
| **CSS**        | Adds styling and visual appearance     |
| **JavaScript** | Adds interactivity and dynamic content |

### Easy way to remember

```text
HTML       → Structure
CSS        → Style
JavaScript → Behavior / Interactivity
```

### HTML

**HTML (HyperText Markup Language)** defines the structure of a webpage.

It can define elements such as:

* Headings
* Paragraphs
* Links
* Images
* Buttons
* Forms
* Sections

HTML provides the structure but does not by itself provide the visual styling of a modern webpage.

### CSS

**CSS (Cascading Style Sheets)** is used to style HTML content.

It can control the appearance of elements such as:

* Colors
* Fonts
* Spacing
* Layout
* Positioning

### JavaScript

**JavaScript** adds interactivity and dynamic behavior to webpages.

For example:

```text
User clicks a button
        ↓
JavaScript executes
        ↓
The webpage changes
```

---

# 4. Static and Dynamic Content

Website content can be **static** or **dynamic**.

## Static Content

**Static content** is content that is already stored on the server.

The server can return this stored content when the client requests it.

```text
Content stored on server
        ↓
Client requests it
        ↓
Server returns it
```

## Dynamic Content

**Dynamic content** is generated when it is requested by the client.

Dynamic content can involve information from other systems and applications, such as databases.

```text
Client Request
      ↓
Server processes request
      ↓
Server obtains required data
      ↓
Database / Other System
      ↓
Server generates response
      ↓
Client
```

### Important

Most websites contain **both static and dynamic elements**.

---

# 5. Databases

Dynamic content can involve information coming from databases.

For example:

```text
User Request
     ↓
Backend
     ↓
Database
     ↓
Data returned
     ↓
Backend processes data
     ↓
Response sent to client
```

Databases allow applications to work with information that is not simply fixed webpage content.

---

# 6. Cloud Applications

**Cloud applications** are similar to websites because they request content from a server and receive a response.

However, cloud applications are designed to work with **cloud-based infrastructure and services**.

Cloud applications can use:

* Cloud-based back-end infrastructure
* Cloud-based data storage
* Cloud-based data processing
* Other cloud services

### Important Characteristics

Cloud applications are designed to be:

* **Scalable**
* **Resilient**

### Scalability

**Scalability** refers to the ability of an application to handle increasing workloads by making additional resources available.

```text
More users
    ↓
More workload
    ↓
Application needs more resources
    ↓
Resources can be scaled
```

### Resilience

**Resilience** refers to the ability of an application to continue functioning despite problems or failures.

---

# 7. Front-End and Back-End

Web and cloud application development can be divided into two primary areas:

```text
                 Web Application
                       │
              ┌────────┴────────┐
              ↓                 ↓
         FRONT-END          BACK-END
         Client-side        Server-side
```

---

# 8. Front-End Development

The **front-end** deals with everything that happens on the **client side**.

In simple terms:

> Front-end = everything the user can see and interact with.

Examples include:

* Webpage layout
* Buttons
* Forms
* Menus
* Text
* Images
* User interactions

Common front-end technologies include:

* HTML
* CSS
* JavaScript
* Frameworks
* Libraries
* Development tools

---

# 9. Back-End Development

The **back-end** deals with everything that happens on the **server side**, before code and data are sent to the client.

Back-end development usually handles:

* Application logic
* Application functionality
* Authentication
* Data-related operations
* Server-side processing

### Authentication

**Authentication** is the process used to verify a user's identity.

For example:

```text
Username + Password
        ↓
Backend verifies credentials
        ↓
User is authenticated
```

Authentication helps keep application data secure.

---

# 10. Databases in Back-End Development

Back-end developers may also work with databases.

Two types mentioned in the course are:

### Relational Databases

Databases that organize data using a relational model.

### NoSQL Databases

Databases that use data models other than the traditional relational model.

In larger projects, back-end developers may work together with **database administrators (DBAs)**.

---

# 11. Full-Stack Development

A **full-stack developer** has skills, knowledge, and experience in both:

* Front-end development
* Back-end development

```text
                 FULL-STACK
                     │
          ┌──────────┴──────────┐
          ↓                     ↓
     FRONT-END              BACK-END
     Client-side            Server-side
          │                     │
    HTML/CSS/JS          Logic/Functionality
                         Authentication
                         Databases
```

### Roles

| Developer                | Main Focus                  |
| ------------------------ | --------------------------- |
| **Front-End Developer**  | Client-side development     |
| **Back-End Developer**   | Server-side development     |
| **Full-Stack Developer** | Both front-end and back-end |

# 13. Code Editor

A **code editor** is a tool primarily used for writing and editing source code.

Examples mentioned in the course include:

* Sublime Text
* Atom
* Vim
* VS Code

---

# 14. IDE

**IDE = Integrated Development Environment**

An IDE provides an integrated environment for developing and managing software.

An IDE provides capabilities beyond basic code editing and can make it easier to build and manage code.

Good IDEs can:

* Support multiple programming languages
* Integrate with development tools
* Integrate with management and storage tools
* Integrate with Git and GitHub
* Support extensions
* Provide themes and customization

Examples mentioned in the course include:

* Visual Studio
* Eclipse
* NetBeans
* VS Code

### Code Editor vs IDE

```text
Code Editor
    ↓
Primarily used to write and edit code

IDE
    ↓
Code editing
+ Additional development capabilities
+ Build tools
+ Debugging
+ Integrations
+ Extensions
```

# 17. Web vs Cloud Applications

### Traditional Web Application

```text
Client
  ↓
Web Server
  ↓
Application / Database
  ↓
Response
  ↓
Client
```

### Cloud Application

```text
Client
  ↓
Cloud-based Application
  ↓
Cloud Backend
  ↓
Cloud Storage / Processing / Services
  ↓
Response
  ↓
Client
```

Cloud applications are designed to work with cloud-based infrastructure and services and are intended to be scalable and resilient.
