# Aspects of the Web Development Lifecycle

## 1. What Is the Web Development Lifecycle?

The **Web Development Lifecycle** describes the different stages involved in developing and delivering a web or cloud application.

It covers the process from the initial idea (**conception**) through:

```text
Conception
    ↓
Design / Architecture
    ↓
Requirements
    ↓
Planning
    ↓
Development
    ↓
Testing
    ↓
Deployment
    ↓
Maintenance
```

The exact activities can vary depending on the application and development team.

---

# 2. Conception

**Conception** is the stage where the application idea is formed and the team determines what needs to be built.

Important activities can include:

* Understanding the idea
* Understanding what stakeholders need
* Thinking about how the application should work
* Considering what technologies and services should be used

### Example

Suppose a company wants to build an online shopping application.

During conception, the team might ask:

* What problem are we solving?
* Who will use the application?
* What should the application provide?
* What technologies or cloud services might we need?

---

# 3. Requirements

Before development begins, developers need to understand what users and stakeholders actually require.

**User requirements** describe what the application needs to provide from the user's or stakeholder's perspective.

For example:

```text
User Requirement:
Users should be able to create an account
and log into the application.
```

Understanding requirements helps the development team build the correct application rather than simply starting to write code without knowing the goal.

---

# 4. Design Thinking

The development process can involve **design thinking workshops** before coding begins.

Design thinking helps teams think about:

* The users
* Their needs
* The problem being solved
* Possible solutions
* How the application should work

The important idea is:

> Development does not begin with writing code immediately. There is planning and problem-solving that happens beforehand.

---

# 5. Sprint Planning

In an Agile development environment, work may be organized into **sprints**.

**Sprint planning** is used to determine what work the development team will focus on during a sprint.

A sprint can involve selecting and organizing tasks that the team intends to complete during that period.

```text
Backlog
   ↓
Sprint Planning
   ↓
Selected Work
   ↓
Development
   ↓
Testing
   ↓
Completed Work
```

---

# 6. Architecture

A **software architect** considers how the application should be built.

Architecture involves decisions such as:

* How the application will be structured
* What services will be used
* What technologies will be required
* How different components will work together
* How to deliver what the stakeholder needs

For cloud applications, architecture may involve deciding which **cloud services** should be used.

### Example

```text
Application
    │
    ├── Front-End
    ├── Back-End
    ├── Database
    └── Cloud Services
```

The architecture stage is important because technical decisions made here influence the rest of development.

---

# 7. Development

**Development** is the stage where developers actually build the application.

This is where developers:

* Write code
* Implement functionality
* Build application components
* Turn the planned design into a working application

Developers may be eager to reach this stage, but the video emphasizes that several activities can happen before the first piece of code is written.

---

# 8. Testing

**Testing** is the process of checking the application to discover problems or bugs.

Testing helps determine whether the application works as expected.

```text
Application
    ↓
Testing
    ↓
Find Bugs
    ↓
Fix Bugs
    ↓
Test Again
```

### Why is testing necessary?

Software can contain bugs even when the code appears to work.

Testing helps ensure that the application is functioning correctly before and after deployment.

The video describes testing as a necessary part of development even though discovering and fixing bugs may not be enjoyable.

---

# 9. Deployment

**Deployment** is the process of making the application available to its users.

A developer's goal can be to deploy the application and hand it to the end user so that it can:

* Make their lives easier
* Make their jobs more effective
* Provide the intended functionality

### Basic idea

```text
Development
     ↓
Testing
     ↓
Deployment
     ↓
End User
```

Deployment can also involve **automated deployment**, which the video identifies as a best practice.

---

# 10. Automated Deployment

**Automated deployment** means using automation to deploy an application rather than performing every deployment step manually.

Conceptually:

```text
Code
 ↓
Build
 ↓
Test
 ↓
Automated Deployment
 ↓
Application Available
```

Automation can make the deployment process more consistent and efficient.

---

# 11. Maintenance

After an application has been deployed, development does not necessarily end.

The application needs **maintenance**.

Maintenance can involve:

* Keeping the application working
* Addressing problems
* Making changes
* Continuing to support the application

The video emphasizes that maintenance is **critical** and can sometimes be under-emphasized.

```text
Deployment
    ↓
Maintenance
    ↓
Updates / Fixes / Improvements
    ↓
Continued Application Use
```

---

# 12. Complete Web Development Lifecycle

The major stages discussed in the video can be remembered as:

```text
CONCEPTION
    ↓
Requirements
    ↓
Design / Architecture
    ↓
Planning
    ↓
DEVELOPMENT
    ↓
TESTING
    ↓
DEPLOYMENT
    ↓
MAINTENANCE
```

The process is not necessarily a simple one-way process. Problems discovered during testing or maintenance can lead to changes and further development.

---

# 13. Different Professionals May Focus on Different Stages

The video includes perspectives from different professionals.

### Developer

A developer may particularly enjoy:

* Writing code
* Building the application
* Deploying the application
* Seeing the application help its users

### Software Architect

A software architect may focus more on:

* Conception
* Architecture
* Choosing services
* Choosing technologies
* Determining how the application should be built
* Delivering stakeholder requirements effectively and economically

### QA / Testing Professionals

Testing can be particularly relevant to **QA-oriented professionals**.

Their work involves finding problems and ensuring that the application behaves correctly.

---

# 14. Stakeholders

A **stakeholder** is someone who has an interest in the application and what it needs to accomplish.

During conception and architecture, the development team considers:

> What does the stakeholder need?

The architecture and technology choices should ultimately help deliver those requirements.

---

| **Conception**                | Formation of the application idea and initial planning                                        |
| **Requirements**              | What users/stakeholders need the application to provide                                       |
| **Design Thinking**           | Approach used to understand users/problems and explore solutions                              |

---

# 16. Quick Revision

### The lifecycle

```text
Conception
→ Requirements
→ Design / Architecture
→ Planning
→ Development
→ Testing
→ Deployment
→ Maintenance
```

### Remember

* **Don't start with code immediately.** Requirements, planning, design, and architecture can happen first.
* **Requirements** tell the team what needs to be built.
* **Architecture** determines how the application can be built.
* **Development** turns the plan into working software.
* **Testing** finds bugs and verifies behavior.
* **Deployment** delivers the application to users.
* **Automated deployment** can improve the deployment process.
* **Maintenance** continues after deployment and is critical.
* Different professionals may enjoy or specialize in different stages of the lifecycle.

## One-Line Mental Model

> **Understand the problem → plan the solution → design the architecture → build it → test it → deploy it → maintain it.**
