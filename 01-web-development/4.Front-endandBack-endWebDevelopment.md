# Front-end and Back-end Web Development

## 1. Front-End vs Back-End

Web development is broadly divided into:

* **Front-end development** — client-side programming
* **Back-end development** — server-side programming

A simple mental model:

> **Front end = what the user sees and interacts with**
> **Back end = the services and processing that make the front end work**

---

# 2. Front-End Development

**Front-end development**, also called **client-side programming**, is what happens in the **browser**.

It includes everything the user:

* Sees
* Touches
* Clicks
* Interacts with directly

Examples include:

* Website design
* Buttons
* Page layout
* User interactions
* Clicking elements
* Shopping cart interface

### Common Front-End Languages

The transcript identifies:

* **HTML**
* **CSS**
* **JavaScript**

### Common Front-End Frameworks and Libraries

Examples mentioned:

* AngularJS
* React
* jQuery
* Backbone.js
* Bootstrap

---

# 3. Back-End Development

**Back-end development**, also called **server-side programming**, happens on the:

* Server
* Database

The back end provides the services that **enable the front-end user experience**.

The user generally does **not directly interact** with these services.

### Common Back-End Languages

The transcript mentions:

* Node.js
* JavaScript

### Common Back-End Frameworks

Examples mentioned:

* Django

* Spring

# 4. Front End and Back End Working Together

The front end and back end perform different jobs but work together.

```text
                WEB APPLICATION
                      │
          ┌───────────┴───────────┐
          │                       │
      FRONT END               BACK END
      Client Side             Server Side
          │                       │
       Browser                Server/Database
          │                       │
   User interaction        Processing/services
          │                       │
          └───────────┬───────────┘
                      │
              Complete application
```

### Simple Example

Imagine an online shopping website.

### Front end

The user can:

* View products
* Click "Add to Cart"
* View the shopping cart
* Navigate through the website

### Back end

When the user performs an action, the back end may:

* Process the transaction
* Process credit-card information
* Generate an invoice
* Handle shipment
* Arrange shipping of the product

So:

> **Front end provides the interface.**
> **Back end provides the services and processing behind that interface.**

# 13. Front-End vs Back-End — Quick Comparison

| Aspect                     | Front End                                        | Back End                                 |
| -------------------------- | ------------------------------------------------ | ---------------------------------------- |
| Also called                | Client-side                                      | Server-side                              |
| Main location              | Browser                                          | Server / database                        |
| User interaction           | Direct                                           | Usually indirect                         |
| Main purpose               | Interface and user interaction                   | Services and processing                  |
| Languages mentioned        | HTML, CSS, JavaScript                            | Python, Java, Node.js, JavaScript        |
| Frameworks/tools mentioned | AngularJS, React, jQuery, Backbone.js, Bootstrap | Django, Rails, Spring, Flask, Express.js |
| Example                    | Shopping cart button                             | Processing the purchase                  |
| User sees it?              | Yes                                              | Usually no                               |

# 14. Important Concepts to Remember

### Client-Side

Code that runs in the browser and handles what the user sees and interacts with.

### Server-Side

Code and services running on the server that support the application's functionality.

### Front End

The visible and interactive part of an application.

### Back End

The services and processing behind the application's user experience.

### Full Stack

Working across front-end, back-end, and potentially infrastructure/cloud components.

### Framework

A structured set of tools and functionality that helps developers build applications.

### Library

Reusable code/components that developers can use in their applications.

### Serverless

A cloud development approach where developers use managed functions/services rather than managing the underlying servers directly.
