# Introducing Application Development Tools

## 1. Application Development Workbench

Getting a cloud application from the **idea stage** to a fully written and deployed application is a long process.

Developers use various tools to make this process easier.

The lesson identifies three important parts of a cloud application developer's workbench:

1. **Version Control**
2. **Libraries**
3. **Frameworks**

---

# 2. Version Control

**Version control systems** keep track of changes made to source code.

They record:

* **What** changes were made
* **When** they were made
* **Who** made them

They can also help **resolve conflicts** when multiple developers make changes to the same project.

### Why Version Control Is Important

Version control is useful even when you are the **only developer** working on a project.

It allows you to:

* Revert to an older version if something goes wrong
* Track how your code developed over time
* Manage different versions of your source code

Because version control is generally tied to the storage system being used, the lesson recommends using a **code repository**, even for beginners.

---

# 3. Git and GitHub

**Git** and **GitHub** are extremely popular for source-code storage and management.

### Git

Git stores files in **repositories**.

With Git, you can:

* Track changes
* Create branches
* Perform focused development on branches
* Merge branches back into the main codebase

### Basic Git Workflow

```text
Main Codebase
      │
      ├── Create Branch
      │
      ↓
Focused Development
      │
      ↓
     Test
      │
      ↓
    Merge
      │
      ↓
Main Codebase
```

### Key idea

> **Version control = safely track and manage changes to code.**

---

# 4. Code Libraries

A **code library** is a collection of reusable code.

Libraries can contain things such as:

* Standard programs
* Subroutines
* Functions
* Other reusable code

They allow developers to reuse existing functionality instead of building everything from scratch.

### Example

Suppose you need a **carousel** for navigation on your website.

Instead of writing all the carousel functionality yourself, you can use a library that already provides the required code.

This saves:

* Time
* Development effort

---

# 5. Advantages of Libraries

Libraries make application development:

* Faster
* Easier
* More reusable

You can integrate **multiple libraries** into an existing project.

You can also research and add a library when you discover that you need a specific function or feature.

### How Libraries Work

When using a library:

1. Your program needs a particular function.
2. Your code calls the required library method/subroutine.
3. The library performs the required operation.
4. Control returns to your program.
5. Your program continues its normal flow.

### Important Concept

> **With a library, you are in control.**

You decide **when** to call the library's functions.

---

# 6. Libraries Solve Specific Problems

Code libraries are generally used to:

* Solve a specific problem
* Add a specific feature or set of features

There are many libraries available, so developers need to research which library is appropriate for their particular requirement.

---

### Apache Commons Proper

A repository containing reusable **Java components**.

# 8. Frameworks

A **framework** provides a standard way to **build and deploy applications**.

Think of a framework as a **skeleton or scaffold** for your application.

You add your own code to the framework's predefined structure.

### Analogy

Think about building a house:

> **Framework = the frame of the house**

The frame provides the basic structure and guides how the rest of the house is constructed.

Similarly, a software framework provides a structure that guides how an application is developed.

---

# 9. Frameworks vs Libraries

The most important difference in this lesson is **who controls the program flow**.

### Library

```text
Your Application
      │
      ↓
You call the library
      │
      ↓
Library performs function
      │
      ↓
Control returns to your application
```

**You are in control.**

### Framework

```text
Framework
    │
    ↓
Controls program flow
    │
    ↓
Calls your code
    │
    ↓
Your code performs required work
```

**The framework is in control of the overall workflow.**

---

# 10. Frameworks Must Be Chosen Early

The framework you intend to use should be determined **early in development planning**.

It should be used from the beginning.

The lesson states that a new framework cannot simply be incorporated into an already existing project.

The chosen framework:

* Dictates the architecture of the program
* Controls program flow
* Determines when certain subroutines and methods are called
* Requires developers to follow a specific structure

---

# 11. Frameworks Have Less Flexibility

Compared with libraries, frameworks provide developers with **less control**.

However, they provide important advantages:

* Standardization
* Efficient development
* Less configuration work
* A predefined application structure

### Key difference

> **Library → You call it.**
> **Framework → It calls your code.**

This is the central concept of this lesson.

---

# 12. Inversion of Control

The fact that a framework controls the program flow rather than the developer is called:

## Inversion of Control (IoC)

Normally:

```text
Your Code → Calls → Library
```

With a framework:

```text
Framework → Calls → Your Code
```

This reversal of control is known as **inversion of control**.

### Why IoC Is Useful

Inversion of control can:

* Standardize applications
* Reduce tedious configuration
* Reduce the number of decisions developers need to make
* Let developers focus more on application code

---

# 13. Opinionated Frameworks

Frameworks that exert a lot of control are called **opinionated frameworks**.

They have strong opinions about how the application should be structured and developed.

They may determine things such as:

* How the workflow should operate
* How code should be written
* Where files should be located
* Even file names

This reduces the number of architectural and configuration decisions the developer needs to make.

### Trade-off

```text
More Framework Control
        ↓
Less Developer Freedom
        +
More Standardization
        +
Less Configuration
```

---

# 14. Frameworks Can Include Libraries

Frameworks often include their own libraries.

The framework can call those libraries when they are needed.

So a framework may provide:

* Overall application structure
* Program workflow
* Libraries
* Standardized development patterns

# 16. Library vs Framework — Important Comparison

| Feature            | Library                                      | Framework                                  |
| ------------------ | -------------------------------------------- | ------------------------------------------ |
| Main purpose       | Solve a specific problem / add functionality | Provide a standard application structure   |
| Who controls flow? | **Developer**                                | **Framework**                              |
| How is it used?    | Developer calls its functions                | Framework calls developer's code           |
| Flexibility        | More flexible                                | Less flexible                              |
| Structure          | You decide how to integrate it               | Framework dictates structure               |
| Architecture       | Generally controlled by developer            | Framework influences/dictates architecture |
| Configuration      | Developer handles more                       | Framework reduces configuration            |
| Example            | jQuery                                       | Django / AngularJS / Vue.js                |

# 17. Version Control vs Library vs Framework

These three tools solve different problems:

| Tool                | Problem It Solves                                          |
| ------------------- | ---------------------------------------------------------- |
| **Version Control** | Managing and tracking code changes                         |
| **Library**         | Reusing code to solve specific problems                    |
| **Framework**       | Providing structure and workflow for building applications |

# 18. Key Definitions

### Version Control

A system for tracking changes to source code and managing different versions.

### Repository

A storage location for code and its version history.

### Branch

A separate line of development used for focused changes before potentially merging them back into the main codebase.

### Library

A collection of reusable code that developers call when they need specific functionality.

### Framework

A predefined structure and workflow used to build applications.

### Inversion of Control

A situation where the framework controls the program flow and calls the developer's code.

### Opinionated Framework

A framework that strongly dictates how an application should be structured and developed.
