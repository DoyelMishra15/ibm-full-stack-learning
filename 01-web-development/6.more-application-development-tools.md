# More Application Development Tools

Cloud application development involves more than writing code. Several tools and practices help developers **build, test, package, and deploy** applications.

The main topics in this lesson are:

1. **CI/CD**
2. **Build Tools**
3. **Packages**
4. **Package Managers**

---

# 1. CI/CD

**CI/CD** refers to the practices of:

* **Continuous Integration (CI)**
* **Continuous Delivery (CD)**
* **Continuous Deployment (CD)**

CI/CD is considered a **DevOps best practice** that enables developers to deliver frequent changes reliably.

---

# 2. Continuous Integration (CI)

**Continuous Integration** is the practice of frequently integrating newly developed code into a shared project.

A CI environment uses a **build-automation server** to ensure that the different code components work together smoothly.

Developers may integrate code:

* At least once a day
* Or even every hour, depending on how quickly the project changes

### CI Process

```text
Developer writes code
        ↓
Code is integrated frequently
        ↓
Application is automatically built
        ↓
Automated tests run
        ↓
Problems are detected
```

### Key idea

> **CI = frequently integrate code and automatically build/test it.**

---

# 3. Continuous Delivery

**Continuous Delivery** begins where Continuous Integration ends.

The process described in the lesson is:

```text
Continuous Integration
        ↓
Automatically build code
        ↓
Automatically test code
        ↓
Continuous Delivery
        ↓
Deploy build to testing/staging environment
```

Continuous delivery makes code changes available in a **testing or staging environment**.

---

# 4. Continuous Deployment

The lesson identifies continuous deployment as another meaning of the second **CD** in CI/CD.

The key distinction to remember is:

* **Continuous Delivery** → changes are deployed to a testing/staging environment and are ready for release.
* **Continuous Deployment** → changes are automatically deployed as part of the deployment process.

The central idea of CI/CD is to make software delivery **frequent and reliable**.

---

# 5. Build Tools

A **build tool** transforms source code into the **binaries needed for installation**.

Build tools can:

* Organize source code
* Set compile flags
* Manage dependencies

They are especially important when:

* Many projects are interconnected
* Multiple developers contribute
* Many dependencies exist
* Many changes need to be coordinated

Without automation, it can be difficult to keep track of:

* What changes were made
* The order of changes
* Dependencies
* What should be included in the next build

Therefore:

> **Build automation is important for keeping complex development processes running smoothly.**

---

# 6. Build Automation

Build automation can automate many tasks developers perform during development.

Examples include:

1. Downloading dependencies
2. Compiling source code into binary code
3. Packaging binary code
4. Running tests
5. Deploying to production systems

A build can be initiated from:

* The command line
* An IDE

---

# 7. Two Categories of Build Tools

The lesson identifies two broad categories.

## 7.1 Build-Automation Utilities

These generate **build artifacts**, such as executables, by:

* Compiling source code
* Linking source code

### Build artifact

A **build artifact** is an output produced by the build process, such as an executable or other deployable output.

---

## 7.2 Build-Automation Servers

Build-automation servers execute build-automation utilities based on:

* A schedule
* A trigger

They help automate the overall build process.

# 9. Packages

After an application has been developed and tested, it needs to be deployed.

To make installation simpler and trouble-free for users, developers can collect the necessary files into a **package**.

A **package** is an archive containing:

* Application files
* Installation instructions
* Metadata
* Dependencies

### Package Metadata

A package can contain information such as:

* Package description
* Package version
* Dependencies

---

# 10. Dependencies

A **dependency** is another package or piece of software that an application requires.

For example:

```text
Application
    │
    ├── Package A
    ├── Package B
    └── Package C
```

If the application requires Package A and Package B, those packages are dependencies.

Package management systems help ensure that required dependencies are installed.

---

# 11. Package Managers

Once an application has been bundled into a package, a **package manager** can be used to distribute and manage it.

Package managers handle tasks such as:

* Finding packages
* Installing packages
* Maintaining packages
* Uninstalling packages
* Updating packages

These operations are generally performed at the user's request.

---

# 12. What Package Management Systems Do

Package management systems can:

### 1. Extract packages

They coordinate with file archivers to extract package archives.

### 2. Verify integrity and authenticity

They can verify:

* Checksums
* Digital certificates

This helps ensure that a package is:

* Intact
* Authentic

### 3. Find and install software

They can:

* Locate software in repositories
* Download software
* Install software
* Update existing software

### 4. Manage dependencies

They ensure that a package is installed together with the other packages it requires.

# 15. CI/CD vs Build Tools vs Packages vs Package Managers

These concepts solve different problems.

| Concept             | Main Purpose                                                                   |
| ------------------- | ------------------------------------------------------------------------------ |
| **CI/CD**           | Automate and improve frequent software integration and delivery/deployment     |
| **Build Tools**     | Build/compile/package source code and automate build tasks                     |
| **Package**         | Bundle application files, installation information, metadata, and dependencies |
| **Package Manager** | Find, install, update, maintain, and uninstall packages                        |

### Mental Model

```text
       SOURCE CODE
            ↓
      Build Tools
            ↓
      Build / Test
            ↓
         Package
            ↓
    Package Manager
            ↓
       Distribution
            ↓
     Deployment
```

CI/CD can automate and coordinate many of these stages.

# 17. Key Definitions

### CI — Continuous Integration

Frequently integrating newly developed code and automatically building/testing it.

### Continuous Delivery

Automatically delivering built code changes to a testing or staging environment.

### Continuous Deployment

Automatically deploying application changes.

### Build Tool

A tool used to transform source code into build outputs/binaries and automate build-related tasks.

### Build Artifact

An output produced by the build process, such as an executable.

### Package

An archive containing application files, installation instructions, metadata, and dependencies.

### Package Manager

A tool that finds, installs, updates, maintains, and uninstalls software packages.

### Dependency

A package or component required by another application or package.
