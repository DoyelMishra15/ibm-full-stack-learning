# The Importance of Back-End Development

## 1. What Is Back-End Development?

A **front-end developer** creates the part of a website or cloud application that the user sees and interacts with.

The front end commonly uses:

* HTML
* CSS
* JavaScript

A **back-end developer** creates and manages the resources needed to respond to requests made by the user through the client.

The back end is responsible for:

* Processing requests
* Supplying data
* Providing services
* Managing server-side functionality
* Handling data securely

### Simple Mental Model

```text
User
  ↓
Front End / Client
  ↓
Request
  ↓
Back End / Server
  ↓
Processing + Database + Services
  ↓
Response
  ↓
Front End
  ↓
User
```

---

# 2. Front-End and Back-End Developers Work Together

Front-end and back-end developers need to work closely together.

Before development begins, both sides need to understand:

* The requirements of the solution
* What their respective components need to do
* How the front end and back end will interact

Throughout the application lifecycle, they continue collaborating to:

* Resolve issues
* Add functionality
* Maintain the application

---

# 3. What Happens to User Data?

Consider an online shopping application.

A user may provide:

* Login information
* Product searches
* Payment information
* Address
* Credit card information

The **back end processes these inputs**.

Back-end developers write and maintain the application components responsible for processing this information.

---

# 4. Example: Searching for a Product

Suppose a user searches for a product.

The process is roughly:

```text
User enters search
       ↓
Front End sends request
       ↓
Web application receives request
       ↓
Back End processes request
       ↓
Database is queried
       ↓
Correct data is retrieved
       ↓
Data is returned to client
       ↓
Front End displays results
```

For this to work, a back-end developer needs to understand:

1. The language used by the web application
2. How to query the database
3. How to retrieve the correct data
4. How to connect the web application and database

---

# 5. User Accounts, Authentication, and Authorization

Back-end development can also involve restricted areas of a website.

For example, some pages may only be accessible to users who:

* Have an account
* Have logged in

Back-end developers may be responsible for:

### User Account Management

Managing user accounts and their associated information.

### Authentication

Determining **who the user is**.

Example:

```text
Username + Password
        ↓
Authentication
        ↓
Is this the correct user?
```

### Authorization

Determining **what the authenticated user is allowed to access or do**.

Example:

```text
Authenticated User
        ↓
Authorization
        ↓
Does this user have permission?
```

### Important distinction

> **Authentication = Who are you?**
> **Authorization = What are you allowed to do?**

---

# 6. Handling Sensitive Information

Purchasing products requires users to submit sensitive information, such as:

* Address
* Credit card number

The back end must ensure that sensitive information is:

* Handled securely
* Stored securely

Security is therefore an important responsibility of back-end development.

---

# 7. Different Front-End Requests Need Different Back-End Services

Front-end interactions can generate different types of requests.

Examples include:

* Requesting data such as an image
* Submitting information through a form
* Sending sensitive information

Each type of request may require a different service from the back-end server.

The back end must determine how to process each incoming request.

---

# 8. APIs, Routes, and Endpoints

Back-end developers use:

* **APIs**
* **Routes**
* **Endpoints**

to process incoming requests.

These provide ways for the front end to communicate with the back end.

---

# 9. API

An **API (Application Programming Interface)** is code that works with data.

The lesson states that APIs commonly work with data using:

* JSON
* XML

APIs have defined:

* Rules
* Structure

APIs allow different types of software to access resources from a back end.

For example:

* Cloud applications
* Mobile applications
* Other software

can use APIs to access back-end resources.

### Simple Model

```text
Front End / Client
       ↓
      API
       ↓
Back-End Service
       ↓
    Database
```

---

# 10. Route

A **route** is a path to a website or page that the user interacts with.

Routes generally:

1. Receive user input
2. Process or route the request
3. Return/display results based on the input

The back end uses routing to determine where an incoming request should go.

---

# 11. Endpoint

An **endpoint** may be:

* An API
* A path

It represents a destination that can handle a particular request.

When a request arrives at the back end, routing directs it to the appropriate service.

### Request Flow

```text
Front-End Request
       ↓
Back-End Server
       ↓
Routing
       ↓
Correct Endpoint
       ↓
Correct Service
       ↓
Response
```

If the appropriate endpoint exists, the request can be handled and a response returned.

If the endpoint does not exist, the server returns:

> **404 error**

---

# 12. Why APIs, Routes, and Endpoints Matter

APIs and routes allow the front-end client to connect to the correct back-end service.

The lesson describes them as effectively allowing the front end to **plug into the correct socket at the back end**.

They provide a mechanism for software to access back-end resources.

# 16. SQL and Databases

Back-end developers frequently work with:

* Data
* Databases

Therefore, learning some **SQL** is beneficial.

SQL is used to work with relational databases and query data.

### Basic flow

```text
Back-End Application
        ↓
       SQL
        ↓
    Database
        ↓
      Data
```

---

# 17. ORM — Object-Relational Mapping

Back-end developers can use **Object-Relational Mapping (ORM)** tools to work with databases.

An ORM can:

* Connect an application to a database
* Retrieve the required data
* Hide some of the complexity of database queries

### Why Learn Database Fundamentals Anyway?

Even though an ORM hides some database-query complexity, developers should still understand database fundamentals.

This helps them:

* Understand what the application is doing
* Troubleshoot database-related issues

### Mental Model

```text
Application
     ↓
    ORM
     ↓
Database
```

The ORM acts as a layer between the application and the database.

# 20. Important Concepts to Remember

### Client

The software through which the user interacts with an application.

### Server

The back-end system that processes requests and provides services/data.

### API

Code/interface that allows software to access back-end resources and work with data according to defined rules and structure.

### Route

A path used to direct requests to a website/page or back-end functionality.

### Endpoint

A destination represented by an API or path that can handle a request.

### Authentication

Verifying the identity of a user.

### Authorization

Determining what an authenticated user is allowed to access or do.

### ORM

Object-Relational Mapping; a tool/layer that helps applications interact with databases while hiding some query complexity.

### SQL

A language used to work with relational databases.
