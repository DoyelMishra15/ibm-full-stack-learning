# 4. HTML5 Document Structure

An HTML5 document can contain several important elements.

A simplified structure is:

```html
<!DOCTYPE html>
<html>
    <head>
        <title>Sample page</title>
    </head>

    <body>
        <!-- Page content -->
    </body>
</html>
```

---

# 5. `<!DOCTYPE>`

The `<!DOCTYPE>` declaration specifies the **document type**.

Important:

> `<!DOCTYPE>` is **not an HTML tag**.

It is an instruction to the browser about the version of HTML that the page is written in.

Although the declaration is not required, the lesson recommends placing it as the **first line** of the HTML code if it is included.

---

# 6. `<html>` — Root Element

The `<html>` element is the **root element** of the HTML document tree.

It contains all other HTML elements, except the `<!DOCTYPE>` declaration.

```text
<!DOCTYPE>
   │
<html>
   ├── <head>
   └── <body>
```

---

# 7. `<head>` Element

The `<head>` element contains information and resources associated with the document.

The example contains a `<title>` element:

```html
<head>
    <title>Sample page</title>
</head>
```

The `<head>` can contain:

* `<title>`
* Scripts
* `<style>`
* Stylesheet links
* Metadata
* Browser-support information
* Other initialization functions

The `<head>` generally contains information needed by the browser rather than the main content displayed to the user.

---

# 8. `<body>` Element

The `<body>` element contains the **content displayed on the webpage**.

For example:

```html
<body>
    <h1>Hello</h1>
    <p>Welcome to my website.</p>
</body>
```

### Basic distinction

```text
<html>
 ├── <head>
 │    ├── title
 │    ├── scripts
 │    ├── styles
 │    └── metadata
 │
 └── <body>
      └── visible webpage content
```

---

# 9. The DOM Tree

When a browser receives an HTML document, it **parses the markup** and turns it into a:

> **DOM — Document Object Model**

The **DOM tree** is an **in-memory representation of a document**.

It represents the document's:

* Type
* Structure
* Elements
* Text
* Comments

---

# 10. DOM Nodes

A DOM tree contains different kinds of **nodes**.

The lesson specifically mentions:

### DOCTYPE Node

Represents the document type.

### Element Nodes

Represent HTML elements such as:

* Headers
* Paragraphs

### Text Nodes

Represent the text contained within elements.

### Comment Nodes

Represent comments in the document.

---

# 11. Example DOM Tree

Given:

```html
<!DOCTYPE html>
<html>
    <head>
        <title>Sample page</title>
    </head>
    <body>
        <h1>Hello</h1>
        <p>Welcome</p>
    </body>
</html>
```

The browser creates an in-memory structure conceptually similar to:

```text
DOCTYPE
   │
 html
 ├── head
 │    └── title
 │         └── "Sample page"
 │
 └── body
      ├── h1
      │    └── "Hello"
      │
      └── p
           └── "Welcome"
```

This hierarchical structure is the **DOM tree**.

# 13. XML

**XML = Extensible Markup Language**

XML documents look similar to HTML documents.

One difference mentioned in the lesson is that an XML document has an **XML declaration/tag on the first line**.

For XML documents, the **Content-Type** must specify an XML media type, such as:

```text
application/xml
```

When a document is transmitted with an XML content type:

```text
Browser
   ↓
XML document
   ↓
XML processor parses it
```

---

# 14. HTML vs XHTML

The choice between HTML and XHTML depends on how the application is intended to be used.

One factor mentioned in the lesson is whether you are using:

**XSLT (Extensible Stylesheet Language Transformations)**

to create other documents and resources from your web pages.

---

# 15. HTML and XHTML — Similarities

HTML and XHTML use the same **semantic tags**.

However, their syntax rules differ.

---

# 16. XHTML Is More Strict

XHTML follows stricter XML-style rules.

### XHTML requires:

* Tags to be written in **lowercase**
* Documents to be **well-formed**
* Every element to have an **end tag**
* Every attribute to have a **value**
* Attribute values to be surrounded by **single or double quotation marks**

Example:

```html
<p class="intro">Hello</p>
```

The element has:

* An opening tag
* A closing tag
* An attribute with a value
* A quoted attribute value

---

# 17. Well-Formed XML/XHTML

A document is **well-formed** when it follows the required XML syntax rules.

If an XML parser encounters syntax that is not well-formed:

> **It stops processing.**

This is an important difference from HTML.

---

# 18. HTML Is Less Rigorous

According to the lesson, HTML syntax is less rigorous than XHTML.

The lesson notes that HTML may allow or commonly encounter:

* Different letter case
* Unmatched quotation marks
* Non-terminated elements
* Uncontained elements

Therefore:

```text
XHTML → stricter syntax
HTML  → less rigorous syntax
```

---

# 19. HTML vs XHTML — Quick Comparison

| Feature          | HTML                 | XHTML                                |
| ---------------- | -------------------- | ------------------------------------ |
| Tag case         | Case does not matter | Lowercase required                   |
| Well-formedness  | Less rigorous        | Must be well-formed                  |
| End tags         | Less strict          | Every element must have an end tag   |
| Attribute values | Less strict          | Must have a value                    |
| Attribute quotes | Less strict          | Must use single/double quotes        |
| Parser behavior  | More forgiving       | XML parser stops on malformed syntax |

# 21. Key Terms

### HTML5

A version/specification of HTML supporting modern web capabilities.

### DOM

**Document Object Model** — an in-memory representation of a document.

### DOM Tree

The hierarchical structure created when the browser parses an HTML document.

### Node

An individual object in the DOM tree, such as an element, text, comment, or DOCTYPE node.

### XML

**Extensible Markup Language** — a markup language with stricter syntax rules discussed in comparison with HTML.

### XHTML

HTML expressed using XML-style syntax and rules.

### XSLT

**Extensible Stylesheet Language Transformations**, mentioned as a technology that can transform documents/resources.

### Content-Type

Information specifying the type of content being transmitted, such as an HTML or XML media type.

## Most Important Mental Model

```text
HTML Document
      ↓
Browser parses markup
      ↓
DOM Tree
      ↓
In-memory representation
      ↓
Nodes
```
